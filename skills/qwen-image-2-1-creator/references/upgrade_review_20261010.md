# v2.0.0 升级交叉审查记录（2026-10-10）

> 审查方式：当前对话没有可启动的独立子代理接口；以下是同一助手按 A/B/C 三种独立职责做的交叉质疑和决策，不声称三个独立模型完成审查。

## 输入任务
用户指出 T2I-only Skill 是错误的范围限定，要求覆盖文生图/文生视频/图像编辑及其他模型能力。

## A：模型能力与官方提示词审查
- **建议**：覆盖原生 T2I、1~10 图编辑、圈选/遮罩、透明RGBA、文字、身份一致性、全景和分镜。
- **证据**：QwenLM 官方 2026-09-20 模型发布与 2026-10-09 Turbo 更新；官方 `system_prompt_t2i.txt` 和 `system_prompt_edit.txt` 独立存在。
- **质询 B**：工作流当前只暴露2个图输入，该如何处理官方上限10图？
- **质询 C**：中文编辑应保留原指令语言，固定文字需逐字检查。

## B：ComfyUI 工程与部署审查
- **建议**：技能负责任务路由、提示词增强契约、用户现有工作流节点注入和结构差异审计。10图节点接线、遮罩、RGBA 等按实际版本验证。
- **回应 A**：脚本不会臆造新 image 输入端口；任务支持10图描述，但超出已有节点端口时显式设为 runtime/graph-change 待办。
- **质询 C**：官方 8步 Turbo checkpoint 自带 sigma 调度，是否要把用户的第三方 Turbo LoRA 统一写成官方 8步？

## C：质量与对照测试审查
- **建议**：区分完整 Turbo checkpoint、第三方 LoRA+Base、普通 Base；保持用户已有 11组工作流不变。
- **回应 B**：不做跨路线单变量归因；任何速度、显存、画质结论必须拿到真实 GPU 日志和图片。
- **回应 A**：文生视频属于外部模型（Wan/H3），Qwen只生成画面/首帧/分镜；纯 T2V 可直接交由视频模型，不将它描述为 Qwen 原生。
